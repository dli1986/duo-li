## 1. 分阶段复习路线

**第一阶段：语言基础巩固**——回顾 class/struct、构造/析构、拷贝与移动语义、运算符重载、模板基础；确保能脱稿讲清楚 RAII、rule of three/five、`const`/引用/指针的组合使用。

**第二阶段：内存与所有权**——智能指针（`unique_ptr`/`shared_ptr`/`weak_ptr`）的适用场景与实现原理；栈 vs 堆；对象生命周期与 dangling reference/悬空指针的常见成因；理解 move semantics 到底优化了什么（而不是死记语法）。

**第三阶段：面向对象与多态**——concrete class / abstract class 的设计意图区别；虚函数、vptr/vtbl、静态类型与动态类型；`override`/`final` 的价值；何时用继承、何时用组合。

**第四阶段：STL 与标准库**——常用容器（`vector`/`map`/`unordered_map`/`set`/`deque`）的底层结构与复杂度特征；迭代器失效规则；算法库（`sort`/`find`/`accumulate` 等）与 lambda 的组合使用。

**第五阶段：并发与系统编程**——`std::thread`/`mutex`/`condition_variable`/`atomic` 的基本用法；数据竞争与死锁的成因；简单的生产者-消费者模型手写练习。

**第六阶段：项目与工程能力**——准备 1-2 个可以深挖的项目（编译期问题排查、性能调优案例、真实 bug 的根因分析），能讲清楚"问题现象 → 排查过程 → 根因 → 修复 → 验证"的完整链路，而不只是背诵结论。

## 2. 练习资源渠道

- **在线判题/练习平台**：LeetCode（C++ 标签）、HackerRank、Codewars——适合巩固语法手感和基础算法。
- **系统设计与八股类资源**：GitHub 上的开源面试题合集仓库（搜索关键词 "cpp interview questions"）、各大科技公司公开的面试准备指南。
- **经典书籍**：《Effective C++》《Effective Modern C++》适合查漏补缺；《A Tour of C++》适合系统过一遍语言全貌；《C++ Primer》适合基础不牢时回炉。
- **真实代码库阅读**：直接阅读成熟开源项目（如 LevelDB、Folly）的源码，比单纯刷题更能建立"good code 长什么样"的直觉，也是本系列笔记的主要方法论。

## 3. 常被问到的基础问题（附作答思路）

**Q1：什么是 RAII？为什么 C++ 需要它？**
作答思路：RAII 把资源生命周期绑定到对象生命周期，构造函数获取资源、析构函数释放资源；C++ 没有垃圾回收，也没有语言层面强制的 `finally` 块，RAII 是在没有这些机制的情况下，依然能保证异常安全和资源不泄漏的核心手段。可以举 `std::unique_ptr`、文件句柄封装、互斥锁的 `lock_guard` 作为例子。

**Q2：`unique_ptr` 和 `shared_ptr` 的区别与适用场景？**
作答思路：`unique_ptr` 表达独占所有权，只能 move 不能 copy，开销几乎等于裸指针；`shared_ptr` 表达共享所有权，内部维护引用计数，多个 `shared_ptr` 可以指向同一个对象，最后一个引用销毁时才释放资源，但有引用计数的原子操作开销，且需要注意循环引用问题（通常用 `weak_ptr` 打破环）。默认应该优先考虑 `unique_ptr`，只有真正需要共享所有权时才用 `shared_ptr`。

**Q3：虚函数是怎么实现运行时多态的？开销在哪？**
作答思路：每个有虚函数的对象通常包含一个隐藏的 vptr，指向该类对应的一张 vtbl；vtbl 里保存虚函数的函数指针；调用虚函数时通过 vptr 找到 vtbl，再按固定 slot 找到函数指针进行间接调用。开销体现在：每个对象多一个指针大小的空间；每次虚函数调用比普通调用多一次间接跳转，通常也无法被内联。

**Q4：`vector` 和 `list`、`map` 和 `unordered_map` 该怎么选？**
作答思路：`vector` 连续内存、随机访问 O(1)、尾部插入摊还 O(1)，但中间插入/删除是 O(n)；`list` 双向链表，任意位置插入/删除是 O(1)（已知迭代器时），但不支持随机访问，且缓存局部性差。`map` 基于红黑树，有序、查找/插入/删除是 O(log n)；`unordered_map` 基于哈希表，平均 O(1) 查找，但没有顺序保证，且需要考虑哈希冲突和负载因子对最坏情况的影响。选择应该基于实际访问模式（是否需要顺序、是否需要频繁随机访问、是否需要频繁中间插入）而不是记忆规则。

**Q5：数据竞争和死锁分别是什么？如何避免？**
作答思路：数据竞争是多个线程未经同步地并发读写同一块内存，且至少一个是写操作，导致行为未定义；避免方法是用互斥锁、原子操作或无锁数据结构保护共享状态。死锁通常发生在多个线程以不同顺序请求多把锁时相互等待；避免方法包括固定加锁顺序、使用 `std::lock`/`std::scoped_lock` 一次性获取多把锁、缩小临界区、避免在持锁时调用可能再次加锁的代码。

## 一句话总结

> 面试准备的重点不是背诵术语定义，而是能把每个概念还原成"它解决了什么真实工程问题、不用它会出现什么具体后果"——这也是这一系列 C++ 笔记贯穿的方法论：从抽象概念出发，落到真实代码（LevelDB 等），再回到可以清楚复述的心智模型。
